# DevTicketManager互換・移行境界契約（P0-022）

## 状態

実データ未受領のため、互換範囲の正式判定は`BLOCKED`。`poc/devticketmanager-compat`に読み取り専用の検証ハーネスを作成し、匿名化済みコピー受領後に同じ手順で再現できる状態を作る。

## 入力と安全境界

- `--input`にはユーザー提供の隔離済み匿名化コピーだけを指定する。
- 入力ディレクトリを再帰的に読み、Markdown以外は読み飛ばす。個別読取エラーは記録し、全体走査を停止しない。
- UTF-8 BOM、UTF-8、Windows code page 932（画面表記はShift_JIS）を判定候補とする。
- PoCは入力へ書き込まず、Front Matter追加、改名、移動、`.adm-meta`作成を行わない。
- 前後のツリーSHA-256が一致することを確認する。

## 互換マッピング（実データ確認前の項目定義）

| 機能 | 判定 | 実データで確認する証拠 |
|---|---|---|
| Markdown一覧・本文 | 保留 | ファイル構成、見出し、文字コード、本文ハッシュ |
| 作成・更新日時 | 保留 | ファイル時刻と文書内日時の意味 |
| 名前・日時ソート | 保留 | 既存一覧との並べ替え比較 |
| 検索 | 保留 | タイトル、本文、ID、部分一致の実例 |
| 確認状態 | 保留 | 既存の状態表現と`.adm-meta`写像候補 |
| 添付関係 | 保留 | Markdown記法、相対パス、欠落時の扱い |
| プロジェクト切替 | 保留 | ルート構成とプロジェクト境界 |

## `.adm-meta`写像方針

確認状態などの補助情報は、元Markdownを変更しない`.adm-meta`オーバーレイへの写像候補として記録する。正式スキーマ、移行操作、既存値の優先順位は実データ確認とP0-023の設計ゲートを経て確定する。PoCは写像案を提示するだけで、変換・一括移行を実行しない。
