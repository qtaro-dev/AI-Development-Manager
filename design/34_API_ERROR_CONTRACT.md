# P1-010 APIエラー契約

## 1. 応答形式

APIエラーは`application/problem+json`で返す。`type`は`/problems/{code}`、`status`はHTTP状態、`detail`と`title`は利用者向けの安全な日本語文言とする。内部例外本文、Stack Trace、ファイルパス、秘密値は応答へ含めない。

拡張項目は次のとおり。

| 項目 | 内容 |
|---|---|
| `code` | UI・クライアントが分岐に利用する安定した英数字コード |
| `messageKey` | 将来の文言辞書で表示文言を管理するキー |
| `inputRetained` | 入力を画面に保持して再編集できるか |
| `retryable` | 同じ入力で再試行できるか |
| `nextAction` | 利用者が次に取る操作の日本語案内 |
| `traceId` | `X-Request-Id`応答値と同じ追跡ID |

## 2. エラー分類

| HTTP | `code` | 例 |
|---:|---|---|
| 400 | `validation_failed` | 入力を修正して再送信 |
| 403 | `forbidden` | 権限を確認 |
| 404 | `not_found` | 一覧を更新して選び直す |
| 409 | `conflict` | 最新版を読み込み確認する |
| 500 | `internal_error` | 時間をおいて再試行し、追跡IDを添えて連絡 |

409の業務固有データ、認証401/403の最終文言、UIトーストは後続チケットで確定する。P1-010では分類と共通形式だけを実装する。

## 3. 変換境界とログ

`ErrorHandlingMiddleware`が予期済みのアプリケーション例外を分類し、未処理例外を`internal_error`へ変換する。404など空のエラーレスポンスも同じ形式へ補完する。P1-008の追跡ミドルウェアが設定したIDを応答とProblem Detailsへ引き継ぐ。

サーバーログへは安全な固定文言、分類コード、例外型のみを記録し、既存の秘密情報マスキング規則を適用する。
