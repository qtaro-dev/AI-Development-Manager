# Markdown解析契約（P0-005）

版: 1.0
状態: P0-005完了・PoC候補
基準日: 2026-08-02

## 1. 入力と不変条件

- 入力はバイト列として読み込み、SHA-256を記録する。
- UTF-8、UTF-8 BOM、Windows code page 932（画面表記はShift_JIS）を判定する。
- 入力ファイルへ書き込まない。解析前後のハッシュ一致を必須とする。
- P0-004の`manifest.yaml`をゴールデン入力契約とし、実データは対象外とする。

## 2. 段階的解析

1. バイト列を文字列へ変換する。
2. `---`区切りのFront Matterを検出する。ない場合は警告とし、本文は保持する。
3. YAMLはYamlDotNetの`YamlMappingNode`から安全なスカラー、配列、マッピングへ変換する。任意.NET型の生成は許可しない。
4. YAMLエラーは文書単位の致命的エラーとして記録し、区切り後の本文は可能な範囲で保持する。
5. Markdown本文をMarkdigで解析し、本文、見出し、GFM表、リンク・添付参照を抽出する。
6. テスト表はヘッダー列と行を抽出し、必須列不足、未知列、128文字超のセルを警告する。巨大セルの正式上限は後続PoCで確定する。

## 3. 結果モデル

結果は、本文と抽出値、警告、致命的エラーを別フィールドで保持する。

| 区分 | 例 |
|---|---|
| 抽出値 | encoding、Front Matter、document_type、見出し、表、添付参照 |
| 警告 | `front_matter_missing`、未知キー、旧schema、`encoding_non_utf8`、表列異常、添付欠落、パス逸脱 |
| 致命的エラー | `front_matter_invalid_yaml` |

1文書のエラーは全体の処理停止へ波及させず、文書単位の結果として返す。

## 4. P0-005検証結果

- P0-004全18fixtureをゴールデン検証できた。
- 正常系・警告系・壊れたFront Matterを期待結果どおりに分離できた。
- 見出し、表列、表行、Front Matter配列の添付参照を抽出できた。
- 同一入力の2回実行で出力が一致した。
- 入力ハッシュは全fixtureで変化しなかった。

Markdig `0.41.3`とYamlDotNet `16.3.0`を本PoCの採用候補として記録する。正式な製品依存関係への採用、Markdown保存・整形、文書種別ヒューリスティックは後続判断とする。
