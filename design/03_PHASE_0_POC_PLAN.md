# Phase 0 技術PoC計画

版: 2.3-p0-024-scan-pipeline
状態: P0-024測定完了、正式採用はP0-023

> この文書はPoCの高水準計画である。実施番号、依存関係、受け入れ条件は`../tickets/phase0/00_PHASE_0_TICKET_INDEX.md`とP0-001～P0-023の個別チケットを正とする。以下の旧P0-01～P0-12番号はテーマ整理用であり、実施チケット番号ではない。

## 1. 実施原則

- 1 PoCを1件の独立チケットとして実施する。
- 製品コードを先に作らず、捨てられる検証コードと測定結果を成果物とする。
- 合否基準、環境、入力データ、結果、判断を記録する。
- 不合格でも結果を削除せず、代替案のADRへつなげる。
- UI基盤PoCと機能実装を混在させない。

## 2. 実施順

### P0-003 詳細評価基準（P0-003_EVALUATION_BASELINE）

成果物は`../poc/common/environment.md`、`../poc/common/workload-profile.md`、`../poc/common/result-template.md`とする。基準PC、Windows 11 64-bit、96 DPI、Edge／Chrome／WebView2、10,000文書、添付分布、5人＋AI 2接続、ウォームアップ、3回以上の測定、最近順位法によるp95、単位、合否、ログ保存先を固定する。

P0-003の完了判定は、後続PoCが同じテンプレートで再現可能に結果を記録できることとし、製品性能の合格判定は各後続PoCで行う。

### P0-004 Markdown検証コーパス

`poc/fixtures/markdown`へ正常系7種と異常系11種の合成fixtureを配置し、`manifest.yaml`へ期待結果とSHA-256を記録した。P0-005以降はmanifestの全fixture存在、ハッシュ一致、期待警告の機械検証を先に実行する。実データ、1万文書性能データ、製品コードは含めない。

### P0-005 Markdown・Front Matter解析PoC

`poc/markdown-parser`でMarkdigとYamlDotNet候補を検証した。P0-004全18fixtureを、文字コード、Front Matter、本文、見出し、表、添付参照、警告、致命的エラーへ分離して解析でき、入力変更なしと決定性を確認した。正式な製品依存関係と巨大セル上限は後続判断とする。

### P0-006 文書種別自動判別PoC

`poc/document-classifier`で、Front Matter、ファイル名、フォルダー、見出し、表構造の順序付きルールを検証した。P0-004全18fixtureは期待種別を満たし、Front Matter付き17件は信頼度1.00、Front Matterなしは`unknown`となった。ファイル名・フォルダー・表構造の合成ケース、未知ケース、手動上書き、入力不変、2回実行の決定性も確認した。ルール閾値と分類種別の正式採用は後続設計ゲートで判断する。

### P0-008 NTFS原子的保存PoC

`poc/atomic-save`で、同一ディレクトリ一時ファイル、Flush、保存前バックアップ、原子的置換、読み取り専用属性復元、使用中ファイル、障害注入、孤立一時ファイル清掃、監査記録を検証した。7シナリオが合格し、原本不変、バックアップ一致、失敗時回復可能性を確認した。ACL保持・継承は製品採用前のWindows実機検証事項として残す。

### P0-009 ETag競合検知PoC

`poc/etag-concurrency`で、内容SHA-256の強いETag、`If-Match`必須、HTTP 409相当の競合応答、HTTP 428相当の欠落拒否、外部エディター更新、同内容再送、双方入力保持、差分取得先、監査記録を検証した。長時間ロックを使わない楽観的排他で、古い画面からの上書きを防止できた。

### P0-010 保存回復ジャーナルPoC

`poc/recovery-journal`で、準備、一時書込み、バックアップ、置換、索引更新待ちの各停止段階からの再起動回復を検証した。期待ハッシュが一致する場合は自動回復し、外部変更は原本を変更せずユーザー判断待ち、壊れたジャーナルは隔離した。同一操作の再回復は二重更新せず、索引再更新を予約し、監査記録を残すことを確認した。

### P0-011 パス境界・リンク安全性PoC

`poc/path-security`で、読取・書込・ダウンロード・アップロード共通の検証サービスを実装した。相対境界、URL二重エンコード、絶対・UNC・デバイスパス、Reparse Point、ADS、予約名、末尾ドット・空白、日本語ファイル名を検証し、危険ケースを拒否した。検査後のリンク差替えは残余リスクとして記録した。

### P0-012 ZIP安全閲覧PoC

`poc/zip-safety`で、500 MiB、1万件、個別250 MiB、合計2 GiB、圧縮率100倍、ネスト2階層、24時間保持の初期上限を設定可能な検査器を実装した。Zip Slip、絶対・重複名、過大ネスト・件数・容量・圧縮率、暗号化・壊れたZIPを拒否し、個別一時閲覧、期限清掃、実行形式のダウンロード専用扱いを確認した。

### P0-013 ファイル走査・監視・再同期PoC

`poc/file-scan-watch`でMarkdownと`.adm-meta` JSONの初回全走査、FileSystemWatcherのデバウンス、スナップショット差分、定期再走査、読込再試行、文書単位エラー、キャンセル・再開、進捗を検証した。監視漏れを再走査で補正し、重複イベントを集約し、ロック中の1文書が全走査を停止しないことを確認した。

### P0-014 SQLite FTS5日本語検索PoC

`poc/sqlite-fts-ja`で`unicode61`と`trigram`を比較した。日本語フレーズ、英数混在、ERRコード完全・部分一致、snippet、ランキング、更新、改名、削除、SQLite削除後の再構築を確認した。SQLiteは正本ではなく検索キャッシュとした。正式tokenizer採用と性能は後続判断とする。

### P0-015 1万文書・同時利用性能PoC

`poc/performance`でP0-003の固定シード負荷モデルを再現した。10,000文書（685,673,224 bytes）、人5・AI 2、3回ウォームアップ除外・20回測定で、初回走査p95 5,141.1ms、候補一覧p95 0.5ms、索引済み検索p95 945.2msを記録した。ETag競合2件を正しく拒否し、索引整合性は維持した。走査と検索は暫定基準未達として、Phase 1改善候補へ分離する。

### P0-016 LAN HTTPS初期設定PoC

`poc/lan-https`でlocalhost限定起動からのCA・Server証明書生成、SAN、397日証明書、クライアント公開証明書、カスタムルート信頼、期限切れ、アドレス変更、Firewall/UAC分離、localhost復帰手順を確認した。実Firewall変更と証明書ストア登録は行わず、確認付き手順として分離した。別PCからの実LAN接続と権限差は製品採用前のWindows実機確認事項とする。

### P0-017 Cookie・APIトークン認証PoC

`poc/auth-token`で、ブラウザ・WebView2共通Cookie属性、CSRF、初回管理者、ログイン失敗・ロックアウト、管理者・編集者・閲覧者、プロジェクト・操作スコープ付きAIトークン、失効・期限切れ、401/403分離、監査ログ秘匿を検証した。18項目すべて合格した。WebView2実ランタイム、HTTPS実接続、永続鍵管理は製品採用前の確認事項とする。

### P0-018 共通Web UI・React採否PoC

`poc/web-ui-react`でReact + TypeScript + ViteのUIサンプルを作成した。チケット一覧・詳細、編集可能なテスト表、保存状態、競合ダイアログ、Cookie認証前提、テーマ、狭幅、検索、キーボード操作をモックAPI契約で確認した。Reactを第一採用候補とするが、Edge／Chrome／WebView2、実IME、DPIの正式確認は後続とする。

### P0-019 大容量添付アップロード・閲覧PoC

`poc/large-attachment`で1ファイル500MiB、1回合計1GiBの境界、ストリーミング、進捗、取消、通信断、再試行、同時アップロード、一時ファイル清掃、Range、PDF・画像・動画・ログ・非対応形式の閲覧方針を検証した。全18項目に合格し、ZIPはP0-012へ分離した。

### P0-01 評価環境とサンプルコーパス

目的: 後続PoCの測定条件を固定する。

内容:

- 基準PC、Windows版、DPI、Edge／Chromeを記録
- 正常、Front Matterなし、壊れたYAML、文字コード違い、巨大表、欠落添付を含むサンプルを作る
- 1万文書の生成条件を定義

依存: なし
後続: すべて

### P0-02 Markdown・Front Matter互換解析

目的: Markdig＋YamlDotNet候補で既存文書を安全に解析できるか確認する。

合格条件:

- Front Matterなし文書の本文を欠落なく表示できる。
- YAMLエラーが文書単位に隔離される。
- テスト表の`item_id`と列を安定して抽出できる。
- 自動判別の根拠と信頼度を説明できる。
- 入力ファイルを変更しない。

依存: P0-01

### P0-03 ローカルNTFS原子的保存・競合・回復

目的: ETag、バックアップ、置換、回復ジャーナルを検証する。

合格条件:

- 古いETagによる更新を拒否できる。
- 保存処理の各段階で強制終了しても、原本または回復可能な一時データが残る。
- 保存失敗時に入力内容をクライアントへ返せる。
- Markdownと`.adm-meta`の更新順序が定義される。

依存: P0-01

### P0-04 パス境界・リンク・ZIP安全性

目的: 登録ルート外アクセスと危険なZIPを拒否する。

合格条件:

- `..`、絶対パス、代替データストリーム、ジャンクション、シンボリックリンク経由の逸脱を拒否する。
- Zip Slip、過大展開、過大ファイル数、高圧縮率、深いネストを制限できる。
- 実行形式をブラウザから実行可能な形で返さない。

依存: P0-01

### P0-05 走査・監視・再同期

目的: FileSystemWatcherの欠落・重複を前提に整合性を保てるか確認する。

合格条件:

- イベントの重複をデバウンスできる。
- 大量コピー、改名、削除後に定期再走査で正しい状態へ戻る。
- 読込中ファイルの再試行が上限付きで動く。
- 走査中もAPIが応答する。

依存: P0-02、P0-03、P0-04

### P0-06 SQLite FTS5日本語検索・1万文書性能

合格条件:

- 索引済み検索95パーセンタイル500ms以内を暫定基準とする。
- SQLite削除後に正本から再構築できる。

依存: P0-02、P0-05

### P0-07 LAN HTTPS初期設定

合格条件:

- Server名またはアドレス変更時の再発行手順がある。
- 失敗時にlocalhostへ戻せる。
- Firewall変更の対象と結果を確認できる。

依存: P0-01

### P0-08 Cookie・APIトークン・WebView2認証

目的: ブラウザ、WebView2、AIクライアントの認証分離を検証する。

合格条件:

### P0-09 共通Web UI技術比較

目的: Reactを正式採用できるか判断する。

同一仕様をReact候補で実装し、必要時だけBlazor WebAssemblyと比較する。

検証画面:

- チケット一覧＋詳細
- 編集可能なテスト表
- 保存状態と競合ダイアログ
- 添付アップロード

合格条件:

- Edge、Chrome、WebView2で主要操作が一致する。
- 日本語IME、Tab、Enter、Esc、Ctrl+Sが期待どおり動く。
- 100、125、150、200% DPIで操作不能な崩れがない。
- ライト／ダーク、狭幅、最小ウィンドウでVol.5を満たす。
- 画面固有コードにテーマ値や文言を散在させない。

依存: P0-08

### P0-10 PDF・動画・ログ・添付配信

### P0-12 DevTicketManager互換PoC

目的: 実データに基づいて最低限の互換範囲を確定する。

### P0-020 バックアップ重複抑制PoC（実施結果）

`poc/backup-dedup`で、SHA-256 blobとmanifest参照による重複抑制、自己完結型の別環境復元、参照・manifest・blob破損時の原本非変更、途中停止の未確定化、30日保持・最低20世代・50 GiB上限・80%警告を確認した。13項目すべて合格。実体は小容量テストデータ、500 MiBは論理比較とし、SDK 10.0.302、runtime 10.0.10を結果へ記録した。正式採用はP0-023で判断する。

### P0-022 DevTicketManager互換PoC（実施結果）

`poc/devticketmanager-compat`で承認済み`input-anonymized`を読み取り専用で検証した。7 Markdownファイルの棚卸し、UTF-8判定、本文・見出し、日時、ソート、検索、確認状態の`.adm-meta`写像候補、添付候補、入力前後SHA-256一致を確認し、9項目すべて合格した。SDK 10.0.302、runtime 10.0.10を記録した。P0-022は完了とし、P0-023には着手していない。

### P0-024 走査パイプライン性能PoC（実施結果）

`poc/scan-pipeline-performance`で10,000件の合成コーパスを工程別に測定した。SDK 10.0.302、Runtime 10.0.10、固定seed 15015を記録し、初回p95 2,083.535ms、変更なし再走査p95 117.721ms、単一変更p95 128.989ms、ピーク約107.8MiBだった。追加・変更・削除・改名、取消、読取失敗、強制ハッシュを含む全判定に合格した。正式採用はP0-023で判断する。
