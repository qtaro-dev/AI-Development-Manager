# バックアップ重複抑制・復元契約（P0-020）

## 暫定採用候補

- NTFS固有機能やクラウドに依存せず、バックアップ集合を`manifest.json`と内容ハッシュblobで自己完結させる。
- 識別子は`algorithm + SHA-256 + byte length`とし、既存blobを再利用する際も実体の長さとハッシュを検証する。
- 復元はmanifest、参照blob、実体ハッシュの順に検証し、検証完了前に復元先を変更しない。既存復元先は`.before-restore`へ退避する。
- 参照欠落、manifest/blob破損、途中停止は失敗として監査し、原本・復元先を変更しない。途中生成物は確定マーカーなしで採用しない。

## 保持・容量ポリシー（暫定）

- 30日保持、文書ごと最低20世代を基本とする。
- 50 GiBまたは空き20%を容量安全上限とし、使用量80%で警告する。
- 容量安全を最低世代より優先する場合でも、削除を黙って実行せず、候補・理由・使用量・上限・最低世代を監査記録へ残す。
- 同一ディスクだけのバックアップはディスク故障対策にならないため、運用上の制約として明記する。

## 判断

P0-020の小容量実体PoCでは、単純コピーに対して20世代・同一500 MiB添付の論理容量を10 GiBから500 MiBへ削減できる候補を確認した。製品コードへの正式採用、容量値、保持優先順位はP0-023で確定する。
