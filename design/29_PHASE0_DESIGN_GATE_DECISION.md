# Phase 0最終レビュー・設計確定記録（P0-023）

## 1. 判定概要

- 判定日: 2026-08-03
- 対象: P0-001～P0-026の既存PoC結果、証拠、設計資料、ユーザー承認事項
- 新規PoC: 実施しない

- Phase 1: 本記録だけでは開始承認とせず、以下の条件を確認したうえでユーザーが開始可否を判断する

「採用」は製品コードへの自動昇格を意味せず、Phase 1で実装する設計方針を意味する。条件付き採用は、明記した検証・運用条件を満たすまで実装範囲または正式値を固定しない。

## 2. PoC結果の監査範囲

P0-001～P0-022および追加性能・安全性PoCのP0-024～P0-026について、各チケット、対応する`design/`契約書、`poc/**/results/`、ユーザー承認記録を突合した。P0-021はワイヤーフレームの仮基準として承認済み、P0-022は匿名化したDevTicketManagerサンプルで互換性確認済み、P0-024～P0-026は測定完了・P0-023判断対象として扱う。

### 保留

- 巨大セル、ZIP容量、添付一括容量、競合内容保持期間（暫定7日）の正式値。
- FTS5の日本語検索品質、標準検索の性能目標、限定trigramを使う検索範囲。
- Windows ACL、容量不足、アクセス拒否、Reparse Point、ADS、UNC/NAS、ウイルス対策ソフトの影響。
- Edge、Chrome、WebView2での進捗・取消・Range、IME、DPI、動画/PDF/サムネイルの正式範囲。
- UIの細かなフォント、余白、アイコン、ボタンサイズ。P0-021の仮基準をPhase 1実機で調整する。
- Phase 1開始そのもの。実装着手はユーザーの開始判断後とする。

### 不採用

- SQLite全文trigram構成: P0-025でDB容量と検索性能の負担が大きく、unicode61候補を補完する方式としても正式候補から除外。
- 自動マージ: P0-009の方針どおり、MVPでは最新版・自分の入力・差分を示し、ユーザーが選択または手動統合する。
- 暗号化ZIPのMVP対応: P0-012の安全境界により非対応とし、明確な案内を表示する。
- 汎用プラグイン基盤、元Markdownを書き換える手動分類、索引を正本とする設計: MVPの範囲・監査性・復元性に反するため採用しない。

## 4. Phase 1への引き継ぎ

1. リポジトリ規約、SDK 10.0.302、CIのビルド・テスト・脆弱性監査を固定する。
2. Markdown、`.adm-meta`、ULID、連番、監査、バックアップを含む保存契約を実装する。
3. 原子的保存、パス境界、ETag、回復ジャーナルを一つの保存サービス境界へ統合する。
4. 走査・監視・再同期・ヘルスチェックをバックグラウンド処理として実装する。
5. SQLite候補を再構築可能な索引として組み込み、日本語品質・性能の受入基準を測定する。
6. HTTPS、Cookie/API認証、権限、CSRF、秘密情報の保存境界を実機で確認する。
7. React UIとワイヤーフレームを実ブラウザ/WebView2、IME、DPIで確認する。
8. 添付のストリーミング、Range、取消、ログプレビュー、ZIP安全境界を実容量で確認する。
9. バックアップ復元、保持、容量警告、障害復旧を運用手順として確定する。
10. DevTicketManager互換サンプルから実データ移行へ段階的に進め、元データを変更しない検証経路を維持する。

## 5. レビュー待ち事項

上記の保留項目と条件付き採用の実機・実データ確認がレビュー待ちである。特に検索品質・性能、Windowsセキュリティ境界、添付容量、ブラウザ互換性、SQLite依存更新の配布確認を、製品コードの正式採用判断前に記録する。P0-023ではこれらの確認を新しいPoCとして実施していない。

## 6. 結論

Phase 0の既存PoC結果は、採用・条件付き採用・保留・不採用の区分に整理でき、統合設計の重大な矛盾はない。Phase 1は、条件付き採用の確認項目と保留値を明示したうえで、ユーザー承認後に開始する。P0-024～P0-026の結果は判断材料として反映済みであり、P0-027以降には着手しない。
