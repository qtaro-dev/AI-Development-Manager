# `.adm-meta`・ULID・連番契約

版: 0.1-p0-007
状態: PoC完了・採用候補（承認済み暫定方針）
基準日: 2026-08-02

## 配置と責務

| パス | 責務 |
|---|---|
| `.adm-meta/project.json` | `schema_version`、プロジェクトID、種別別次回連番 |
| `.adm-meta/documents/<ULID>.json` | 不変文書ID、種別、連番、相対パス、内容SHA-256 |
| `.adm-meta/users/<user>/documents/<ULID>.json` | 利用者別確認状態、手動分類オーバーレイ |
| `.adm-meta/documents.lock` | 連番採番の排他 |

文書メタデータと利用者状態を別ファイルにする。手動分類は元Markdownを変更せず、`.adm-meta`側で自動判定より優先する。

## ID・保存契約

- ULIDを不変文書IDとして生成し、文書メタデータのファイル名に使用する。
- 連番は文書種別ごとに1から採番し、排他ロック下で次回値を更新する。
- 削除済みの連番は再利用しない。
- JSONは同一ディレクトリ内の一時ファイルへ書込み、Flush後に置換する。
- SQLiteは正本とせず、削除されても`.adm-meta`の補助情報が残る。
- 内容SHA-256が一致する別パスは改名候補とするが、自動確定しない。単一候補でもユーザー確認を必須とし、確定時は実行者、日時、旧パス、新パス、判定根拠を監査記録へ残す。

暫定スキーマを含め、すべての`.adm-meta` JSONは`schema_version`を必須とする。更新時は更新前バックアップ、段階移行、失敗時復元、監査記録を前提とし、正式JSONスキーマはP0-023で確定する。

## PoC結果

`poc/adm-meta`で35文書の同時採番を実施し、ULID・種別別連番の重複なしを確認した。利用者状態の分離、改名・内容変更・複製候補、原本Markdown不変、原子的サイドカー保存を検証した。.NET SDK 10.0.302、Runtime 10.0.10を使用した。
