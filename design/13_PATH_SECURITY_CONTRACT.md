# パス境界・リンク安全性契約

版: 0.1-p0-011
状態: PoC完了・採用候補
基準日: 2026-08-02

## 共通検証契約

読取、書込、ダウンロード、アップロードは同一の`SafePathService`を使う。入力をURL復号（二重まで）、相対パス検証、ルート内実体解決、Reparse Point検証、Windows固有名検証の順に確認する。

拒否対象は、`..`、絶対・UNC・デバイスパス、ルート外解決、シンボリックリンク・ジャンクション等のReparse Point、ADS、予約名、末尾ドット・空白、危険なアップロード名とする。通常のプロジェクト内パスと日本語ファイル名は許可する。

内部拒否理由（監査・診断用）と、利用者向けの「指定されたパスは安全のため利用できません。」を分離する。

## PoC結果

`poc/path-security`で正常3件、危険10件を検証し、4操作すべてに共通規則を適用した。シンボリックリンク、URL二重エンコード、ADS、予約名、末尾ドット・空白、日本語名を確認した。.NET SDK 10.0.302、Runtime 10.0.10を使用した。

## 制約・未決事項

- 検査と利用の間のリンク差替えはTOCTOUリスクとして残る。
- 製品では安全なハンドル、ACL、再検証を組み合わせる。
- ファイルを開く直前の再検証と安全なハンドル利用を候補として設計する。
- ジャンクション、Reparse Point、ADS、予約名、ACLはWindows実機追加確認へ分離する。
- 利用者向け拒否文言は専門用語を避け、「安全でない保存先です」「このファイル名は使用できません」等とする。
- ジャンクション、ADS、予約名のWindows実機試験を追加する。
- 製品コードへの正式採用はP0-023で判断する。

## P2-002 Local Project Root検証

Local Projectの登録入口では、Windows Adapterの`IProjectRootValidator`だけが入力Rootを
`ValidatedProjectRoot`へ変換する。絶対ローカルパス、存在するディレクトリ、NTFS、Rootと祖先の
Reparse Pointなし、予約名・末尾ドット／空白なし、アクセス可能であることを確認し、その他の入力は
Applicationの安定したProject error codeへ変換する。検証はRoot配下を走査せず、Project内容も変更しない。

これは検査と利用の間のTOCTOUを解消するものではない。後続の読取直前再検証とsafe handle利用を
追加できるよう、検証済みRootの値だけをApplicationへ渡す。
