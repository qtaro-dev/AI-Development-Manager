# P0-015 1万文書・同時利用性能PoC

## 目的

1万文書、同時利用者5名、AIクライアント2接続の基準で、走査・検索・更新の暫定性能目標を検証する。

## 前提・依存関係

- P0-009完了
- P0-013完了
- P0-014完了

## 対象範囲

- 初回走査と再走査
- 一覧候補取得
- 検索
- ETag付き更新競合
- CPU、メモリ、ディスク、応答時間

## 対象外

- UI描画性能
- 大容量動画アップロード
- インターネット越しの負荷
- 本番チューニング

## 対象ファイルまたは対象モジュール

- `poc/performance`
- P0-003負荷モデル
- P0-013、P0-014成果物

## 具体的な実装内容

1. 1万文書データを再現可能に生成する。
2. コールド／ウォーム条件を分ける。
3. 5人相当の閲覧・検索・更新とAI 2接続の読取を流す。
4. 95パーセンタイルと資源使用量を記録する。

## テスト内容

- 初回走査時間
- 一覧初回取得3秒以内の暫定基準
- 索引済み検索95パーセンタイル500ms以内の暫定基準
- 競合更新の正確性
- 負荷終了後の索引整合

## 受け入れ条件

- 全測定がP0-003形式で再現できる。
- 目標未達項目は原因候補とPhase 1対策が分離される。
- 正確性を犠牲にした測定結果を採用しない。

## ユーザーが目視確認する内容

- 目標と測定値の比較表。
- 遅い処理と利用者への影響。

## 想定されるリスク

- 基準PC依存。
- キャッシュ済み結果だけを測って過大評価する。

## 完了後に更新すべき設計資料

- 非機能要件
- 検索・走査設計
- Phase 1以降の性能関連候補一覧

## 実装・実測結果（2026-08-02）

### 実装

- `poc/performance`に.NET 10コンソールPoCを追加した。
- P0-014の`Adm.Search.Sqlite`をProjectReferenceで利用し、製品コードへ昇格させていない。
- P0-003の負荷分布を固定シード`15015`で生成する。
- 初回走査、候補一覧、SQLite FTS5検索、7クライアント相当の読取・検索・更新、ETag競合、索引整合性、CPU・メモリ・ディスクを測定する。
- 結果は一時領域の`result.json`と`run.log`へ保存する。

### 再現コマンド

```powershell
dotnet build .\poc\performance\Performance.Poc.sln --configuration Release
dotnet .\poc\performance\src\Performance.Poc\bin\Release\net10.0\Performance.Poc.dll
```

### 判定・レビュー待ち事項

P0-003形式で再現可能な測定環境、測定条件、ログ保存先、合否判定を実装した。候補一覧とETag競合・索引整合性は合格した。初回走査と検索は暫定性能基準未達であり、Phase 1改善候補（増分走査、索引投入方式、Tokenizer・容量の再評価、メモリ監視）へ分離する。検索結果の省略など正確性を犠牲にする対策は採用しない。

SQLite依存で`SQLitePCLRaw.lib.e_sqlite3 2.1.11`のNU1903（既知の高重大度脆弱性）が発生しているため、正式採用前に依存バージョンと脆弱性対応を確認する。正式な性能SLO、Tokenizer、巨大セル上限、ZIP容量値はP0-023で確定する。
