# P0-014 SQLite FTS5日本語検索PoC

## 目的

SQLite FTS5がMVPの日本語キーワード検索とエラーコード検索に適するか判断する。

## 前提・依存関係

- P0-005完了
- P0-013完了

## 対象範囲

- Unicode61、Trigram、必要時の軽量分割比較
- ファイル名、見出し、本文、状態、関連ID
- 一致箇所、snippet、ランキング
- キャッシュ削除と再構築

## 対象外

- 意味検索
- ベクトルDB
- 類似不具合検索
- 検索画面本実装

## 対象ファイルまたは対象モジュール

- `poc/sqlite-fts`
- 設計候補: `Adm.Search.Sqlite`

## 具体的な実装内容

1. 同じ日本語データを各tokenizer候補で索引化する。
2. 完全語、部分語、英数混在、エラーコードを比較する。
3. 検索結果に参照ファイルと一致箇所を付ける。
4. Markdownと`.adm-meta`からの全再構築を実行する。

## テスト内容

- 日本語名詞、送り仮名、英数、記号を含む検索セット
- `ERR-1234`等の完全一致・部分一致
- 更新、削除、改名後の索引整合
- SQLite削除後の再構築

## 受け入れ条件

- MVP検索例に対する期待結果と順位を満たす。
- 採用tokenizerと既知の制約を説明できる。
- SQLiteが正本になっていない。

## ユーザーが目視確認する内容

- 同じ検索語に対する候補別結果比較。
- 根拠ファイルと一致箇所の表示例。

## 想定されるリスク

- Trigramによる索引容量増加。
- 日本語分割ライブラリ導入による配布負担。

## 完了後に更新すべき設計資料

- 検索・索引仕様
- ADR-009
- 非機能要件

## 実施結果

- 実施日: 2026-08-02
- 実装: `poc/sqlite-fts-ja`
- SDK: .NET SDK 10.0.302（`dotnet --version`実測値: 10.0.302、Runtime: 10.0.10）
- tokenizer候補: SQLite FTS5 `unicode61`、`trigram`。
- 検証: 日本語フレーズ、英数混在、ERRコード完全・部分一致、snippet、ランキング、更新、改名、削除、SQLite削除後の再構築。
- 結果: 両候補の検索特性を確認し、SQLiteを再構築可能なキャッシュとして扱えることを確認。
- 依存警告: `SQLitePCLRaw.lib.e_sqlite3 2.1.11`でNU1903（高重大度の既知脆弱性）が発生。正式採用前に修正版・代替依存を再評価する。
- 判定: PoC合格、正式採用は保留。P0-015以降は未着手。

## レビュー待ち事項

- `unicode61`と`trigram`の正式tokenizer選択。
- SQLite依存パッケージの脆弱性解消。
- 1万文書での検索・再構築性能（P0-015）。
- 製品コードへの正式採用（P0-023）。
