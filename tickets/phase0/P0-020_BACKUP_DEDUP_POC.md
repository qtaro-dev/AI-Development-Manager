# P0-020 バックアップ重複抑制PoC

## 目的

30日・文書ごと20世代を維持しつつ、動画等の大容量添付の重複保存を安全に抑える方式を決める。

## 前提・依存関係

- P0-008完了
- P0-010完了
- P0-019完了

## 対象範囲

- 単純コピー基準
- 内容ハッシュによる重複検知
- 参照管理またはNTFS機能候補
- 復元の自己完結性
- 50 GiBまたは空き20%上限
- 80%警告と世代整理

## 対象外

- クラウドバックアップ
- UNC／NASバックアップ
- 製品用復元画面
- OS全体バックアップ

## 対象ファイルまたは対象モジュール

- `poc/backup-dedup`
- 設計候補: `Adm.Backup`
- バックアップmanifest案

## 具体的な実装内容

1. 同じ500 MiB添付を複数世代で保存する比較を行う。
2. ハッシュ衝突対策と参照整合検査を定義する。
3. バックアップ集合を別環境へ移して復元できるか確認する。
4. 参照欠落、破損、途中停止からの扱いを決める。
5. 保持日数、最低世代、容量上限の優先順位を検証する。

## テスト内容

- 同一添付、同名別内容、別名同内容
- 参照先欠落、破損、manifest破損
- 復元前退避と復元後ハッシュ確認
- 80%警告、上限到達、最低20世代との衝突
- 処理途中の強制停止

## 受け入れ条件

- 採用方式が単純コピーより削減効果を示す。
- バックアップ単位を別環境で検証・復元できる。
- 参照破損時に原本を変更しない。
- 採用しない場合も理由と容量見積が記録される。

## ユーザーが目視確認する内容

- 方式別の容量、復元時間、複雑性比較。
- 容量警告と整理候補の表示案。
- 復元結果の証拠一覧。

## 想定されるリスク

- 重複排除参照の破損で複数世代を失う。
- ハッシュ計算時間とI/O増加。
- NTFS固有機能への過剰依存。

## 完了後に更新すべき設計資料

- バックアップ・復元仕様
- ADR-014
- 管理設定仕様
- 非機能要件

## 実施結果（2026-08-02）

### 実施内容

- `poc/backup-dedup`に.NET 10 console PoCを分離して作成した。
- SHA-256、バイト長、manifest/blob参照で同一内容を共有し、別名同内容は共有、同名別内容は分離する方式を確認した。
- manifestとblobを別環境へコピーして復元し、復元前退避を作成した。
- 参照欠落、blob破損、manifest破損、途中停止では復元先を変更しないことを確認した。
- 30日保持、文書ごと最低20世代、50 GiB上限、80%警告、最低世代との容量競合の監査方針を確認した。

### PoC結果

- 13項目すべてPASS。
- 同一500 MiB添付を20世代保存する論理比較では、単純コピー10,000 MiBに対し重複抑制500 MiB相当となり、約95%削減となる。
- 実体は小容量テストデータのみで、500 MiBファイルは生成していない。
- 候補方式は`dedup_by_sha256_blob_reference`。NTFS固有機能には依存しない。
- 容量値、保持優先順位、正式採用はP0-023で確定する。

### 測定環境・証拠

- SDK: .NET 10.0.302（リポジトリ直下`global.json`で固定）
- Runtime: .NET 10.0.10 / Windows x64
- 結果JSON: `%TEMP%\AI-Development-Manager\poc\P0-020\20260802T121733Z-6b4dae3d5458412895f0b8196a350542\result.json`

### 判定

受け入れ条件を満たしたため、P0-020を完了とする。ただし製品コードへの正式採用はP0-023の設計ゲート待ちとする。
