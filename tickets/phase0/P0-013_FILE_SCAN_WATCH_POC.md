# P0-013 ファイル走査・監視・再同期PoC

## 目的

FileSystemWatcherの重複・欠落を前提に、Markdownと`.adm-meta`の索引状態を最終的に正しくできることを確認する。

## 前提・依存関係

- P0-005完了
- P0-007完了
- P0-011完了

## 対象範囲

- 初回全走査
- FileSystemWatcherとデバウンス
- 定期差分再走査
- 手動再走査
- 読込中ファイルの上限付き再試行
- 走査進捗と文書単位エラー

## 対象外

- 検索ランキング
- サムネイル生成
- UNC／NAS監視

## 対象ファイルまたは対象モジュール

- `poc/file-scanner`
- 設計候補: `Adm.Indexing.Scanner`、`Adm.Indexing.Watcher`

## 具体的な実装内容

1. 走査スナップショットと差分計算方法を作る。
2. 監視イベントを作業キューへ集約する。
3. 定期再走査で監視漏れを修正する。
4. 走査キャンセル、再開、進捗、エラーを記録する。

## テスト内容

- 大量コピー、連続保存、改名、削除
- Markdownと`.adm-meta`の同時変更
- 読込中ロックと再試行
- 監視イベントを意図的に欠落させた後の再同期
- 走査中のヘルスチェック応答

## 受け入れ条件

- 最終再走査後に実ファイルと索引候補が一致する。
- 重複イベントで同じ文書を無限処理しない。
- 1文書の失敗で全走査が停止しない。

## ユーザーが目視確認する内容

- 走査進捗、完了、読取エラーの表示例。
- 手動再読み込みの結果が確認できること。

## 想定されるリスク

- 大量イベントによるキュー膨張。
- 外部ツールの保存方式ごとの差異。

## 完了後に更新すべき設計資料

- ファイル走査仕様
- 索引更新仕様
- 非機能要件

## 実施結果

- 実施日: 2026-08-02
- 実装: `poc/file-scan-watch`
- SDK: .NET SDK 10.0.302（`dotnet --version`実測値: 10.0.302、Runtime: 10.0.10）
- 対象: Markdownと`.adm-meta`配下のJSON。
- 検証: 初回全走査、FileSystemWatcherデバウンス、改名・削除・追加差分、監視漏れの再同期、ロック中ファイル再試行、文書単位エラー、キャンセル・再開、進捗。
- 結果: 最終再走査後の実ファイルと索引候補の一致、重複イベントの集約、1文書エラーによる全走査停止なしを確認。
- 判定: 合格。P0-014以降は未着手。
