# P0-021 主要画面ワイヤーフレーム確定

## 目的

Vol.5とユーザー提供のUI基準画像に基づき、主要画面の配置、情報優先順位、操作導線を実装前に確定する。

## 前提・依存関係

- P0-018完了
- P0-019完了
- ユーザーからUI基準画像を受領済みであること

## 対象範囲

- 初回設定
- プロジェクト
- チケット一覧／詳細
- 添付閲覧
- テスト実施
- 検索
- バックアップ／復元
- 設定
- 狭幅、標準幅、広幅

## 対象外

- 製品UIコード
- AIチャット、Penguin Assistant
- Phase 1 Component実装
- 基準画像にない独自デザイン刷新

## 対象ファイルまたは対象モジュール

- `design/ui/wireframes/`
- `design/ui/screen-inventory.md`
- `design/ui/design-tokens.md`
- ユーザー提供UI基準画像

## 具体的な実装内容

1. 提供画像を最優先基準として画面ごとの責務を割り当てる。
2. 配置、幅、高さ、余白、整列、状態、主要操作をワイヤーフレーム化する。
3. WPF限定操作と共通Web操作を表示上区別する。
4. 保存、競合、アップロード、エラーの状態を作る。
5. ユーザー確認後に基準画像とデザイントークンを版管理する。

## テスト内容

- Vol.5 UI Review Checklist
- ライト／ダーク想定
- 100、125、150、200% DPI想定
- キーボード導線
- 狭幅で主要操作が消えないこと
- 一画面一責務

## 受け入れ条件

- 全主要画面の主目的と次の操作が一意である。
- 提供画像との主要レイアウトと視覚バランスが一致する。
- ユーザーが基準画面として承認する。
- 実装AIが独自解釈しなくてよい寸法・状態情報がある。

## ユーザーが目視確認する内容

- 全ワイヤーフレーム。
- 提供画像との差分一覧。
- ライト／ダーク、幅別、状態別の代表画面。

## 想定されるリスク

- UI基準画像の不足。
- PoC UIをそのまま完成デザインとして流用する誤解。
- 画面数を増やしすぎる。

## 完了後に更新すべき設計資料

- UI・UX設計
- 画面一覧
- デザイントークン
- UI回帰基準
- ADR-0002の参照先

## 実施結果（2026-08-02）

### 変更内容

- `design/ui/screen-inventory.md`に初回設定、プロジェクト、チケット一覧／詳細、添付閲覧、テスト実施、検索、バックアップ／復元、設定の9画面を登録した。
- `design/ui/design-tokens.md`に標準幅・狭幅の寸法、ライト／ダークの色、文字、フォーカス、将来の容量表示単位要望を定義した。
- `design/ui/wireframes/`に標準幅、820px狭幅、保存・競合・アップロード・容量警告・エラー・復元状態のSVGを追加した。
- `design/ui/ui-regression-checklist.md`にレイアウト、キーボード、状態、テーマ、DPI、ブラウザ、IMEの確認項目を追加した。
- 製品UIコードは作成・変更していない。P0-018 PoCを基にした設計成果物のみを作成した。

### 検証結果

- SVG 3点をXMLとして検証し、正常に読み込めることを確認した。
- 画面一覧9画面すべてに主目的、主操作、次の操作、WPF固有操作を定義した。
- 標準幅1440px、狭幅820px、代表状態6種をワイヤーフレーム化した。
- ユーザー提供のUI基準画像は未受領のため、画像との差分確認と正式承認は保留する。

### 判定

仮ワイヤーフレーム、画面一覧、トークン、回帰基準の作成を完了した。P0-021は成果物作成完了・ユーザー承認待ちとして扱い、P0-022以降には着手していない。
