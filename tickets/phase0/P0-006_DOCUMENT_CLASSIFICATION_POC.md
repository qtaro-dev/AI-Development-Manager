# P0-006 文書種別自動判別PoC

## 目的

Front MatterがないMarkdownを、根拠と信頼度を示して判別する方式を確定する。

## 前提・依存関係

- P0-005完了

## 対象範囲

- Front Matter、ファイル名、フォルダー、見出し、表構造の優先順位
- MVP文書種別と`unknown`
- 信頼度と判別根拠
- 手動分類が自動分類を上書きする規則

## 対象外

- AIモデルによる分類
- 原本へのFront Matter自動追加
- 分類UI本実装

## 対象ファイルまたは対象モジュール

- `poc/document-classifier`
- 設計候補: `Adm.Documents.Classification`
- P0-004コーパス

## 具体的な実装内容

1. 判別ルールをデータ化し、順序と根拠コードを定義する。
2. 複数ルールが競合する場合の扱いを決める。
3. `unknown`へ落とす閾値を定義する。
4. 手動分類オーバーレイ適用前後の結果を分離する。

## テスト内容

- 各fixtureの期待種別、根拠、信頼度を検証する。
- 矛盾するファイル名と本文を持つケースを確認する。
- 判別不能を無理に既知種別へ分類しないことを確認する。

## 受け入れ条件

- 判別結果から採用根拠を説明できる。
- Front Matterを最優先する。
- 低信頼度を`unknown`として表示できる。
- 入力Markdownを変更しない。

## ユーザーが目視確認する内容

- 判別例と「なぜこの種類と判断したか」の平易な表示案。
- 判別不能時の手動分類導線案。

## 想定されるリスク

- プロジェクト固有命名を一般規則として固定する。
- 信頼度が見かけ上の精密さを与える。

## 完了後に更新すべき設計資料

- 文書種別仕様
- 判別ルール表
- 未決事項台帳

## 実施結果

- 実施日: 2026-08-02
- 実装: `poc/document-classifier`
- SDK: .NET SDK 10.0.302（ルート`global.json`で固定）
- 依存候補: YamlDotNet 16.3.0。正式な製品採用はP0-023で判断する。
- 判定優先順位: Front Matter、ファイル名、フォルダー、見出し、表構造。
- 判定結果: 種別、信頼度、根拠コードを出力。競合・判定不能は`unknown`。
- 手動分類: 自動判定とは分離したオーバーレイとして適用。
- 検証: P0-004の18fixture、合成5ケース、入力不変、2回実行の決定性を確認。
- 判定: 合格。P0-007以降は未着手。
