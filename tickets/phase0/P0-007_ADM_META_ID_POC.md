# P0-007 `.adm-meta`・ULID・連番仕様PoC

## 目的

既存原本を変更せず、確認状態、手動分類、不変ULID、人向け連番を安全に保持できることを確認する。

## 前提・依存関係

- P0-005完了

## 対象範囲

- `.adm-meta`ディレクトリ構成
- 文書メタデータと利用者固有情報の分離
- ULID採番と連番採番
- 外部改名・移動の追跡候補
- 原子的なサイドカー保存

## 対象外

- ユーザー認証情報の保存
- SQLiteだけを正本にする方式
- 既存MarkdownへのID書戻し

## 対象ファイルまたは対象モジュール

- `poc/adm-meta`
- 設計候補: `Adm.Metadata`
- `.adm-meta/project.json`
- `.adm-meta/documents/`
- `.adm-meta/users/`

## 具体的な実装内容

1. JSONスキーマと`schema_version`を定義する。
2. 文書メタとユーザー確認状態を別ファイルにする。
3. ULIDと種別別連番の衝突防止方法を検証する。
4. 相対パス、内容指紋、候補一致を用いた外部改名検出を試す。
5. 曖昧な一致を自動確定しない。

## テスト内容

- 同時採番でULIDと連番が重複しないこと。
- ユーザーAの確認状態がユーザーBへ影響しないこと。
- MarkdownのハッシュがPoC前後で一致すること。
- 改名、内容変更、複製の各ケースを区別できること。

## 受け入れ条件

- SQLiteを削除しても補助情報が残る。
- 既存Markdownを変更しない。
- 曖昧な移動追跡がユーザー確認待ちになる。
- スキーマ更新方針が定義される。

## ユーザーが目視確認する内容

- `.adm-meta`の配置例。
- 確認状態とチケット進行状態が別であること。
- 改名候補が曖昧な場合の案内文。

## 想定されるリスク

- サイドカーファイル数が増える。
- 外部コピーを改名と誤認する。
- 連番採番の競合。

## 完了後に更新すべき設計資料

- Markdown／Front Matter仕様
- `.adm-meta`データ仕様
- ID仕様ADR

## 実施結果

- 実施日: 2026-08-02
- 実装: `poc/adm-meta`
- SDK: .NET SDK 10.0.302（`dotnet --version`実測値: 10.0.302、Runtime: 10.0.10）
- `.adm-meta/project.json`、`documents/<ULID>.json`、`users/<user>/documents/<ULID>.json`を分離して保存。
- ULIDは16バイトの時刻＋乱数から生成し、種別別連番は排他ロック下で採番。
- 同一ディレクトリ内の一時ファイル、Flush、置換による原子的保存を検証。
- 内容SHA-256による改名候補を提示し、候補は常に確認待ち。複製・同一内容複数候補を自動確定しない。
- 利用者Aの確認済み手動分類が利用者Bへ影響しないことを確認。
- 35文書の同時採番、原本Markdown不変、内容変更時の候補なしを確認。
- 判定: 合格。P0-008以降は未着手。
